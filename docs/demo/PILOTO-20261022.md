# Process AI Studio: piloto com Claude (22/10/2026)

**Estado:** GO para demonstrar geração real por IA. A jornada completa foi ensaiada no Chromium contra a API real, com Claude Sonnet via Claude Code CLI, PostgreSQL descartável e somente texto sintético. Fluxo ensaiado: pedido vago → perguntas → respostas → proposta válida → refinamento → placar. As capturas estão em [`piloto-20261022/`](piloto-20261022/).

## Mensagem central

> **A casca define o piso, o modelo define o teto e a avaliação prova os dois.**

A LLM interpreta e propõe. O backend decide o que vira processo: valida o schema, confere a evidência de cada etapa no texto do solicitante, compila o ProcessSpec e gera o BPMN e os formulários de forma determinística. Por isso o provider pode ser trocado por configuração, e o placar mede o efeito de cada troca.

## O que mudou neste incremento

| Fase | Entrega | Onde |
|---|---|---|
| 1 | Provider `claude-cli` (Claude Code CLI local), isolado: sem ferramentas, MCP, settings ou sessão, em diretório temporário vazio, com saída validada por `--json-schema` | `src/modules/providers/claude-cli-provider.ts` |
| 1 | Placar de avaliação: 12 cenários sintéticos rodados pela API real, com cobertura, invenções, perguntas, latência e custo | `scripts/eval/` · `npm run eval:claude` · `reports/eval/SCOREBOARD.md` |
| 1 | Correção: a normalização descarta os bindings de papel emitidos pelo modelo em vez de reprovar a resposta inteira (9 testes estavam quebrados na `main` desde 18/10) | `src/modules/ai/interpretation-context.ts` |
| 2 | Erros orientados à ação: cada código vira categoria, título, mensagem e ações (`recovery`), e o texto do usuário é preservado | `src/modules/ai/recovery-guidance.ts` · `RecoveryCard` |
| 2 | Omissão do modelo (o usuário disse e o modelo deixou de fora) vira **uma** correção dirigida ao modelo, e não uma pergunta ao usuário | `orchestrator.ts` · `IntentCompilationError.origin` |
| 3 | Gate de prontidão determinístico: um pedido vago recebe um resumo do que foi entendido e até 3 perguntas antes da 1ª proposta | `src/modules/ai/readiness.ts` · `AI_READINESS_GATE` |
| 3 | Painel "O que entendi / O que falta", com a origem de cada item (você descreveu / sua resposta / inferido) | `GET /design-sessions/:id/understanding` · `UnderstandingPanel` |
| 4 | Telemetria por turno: custo, tokens, cache de prompt, chamadas e etapas do pipeline | `GET /design-sessions/:id/telemetry` · `TelemetryPanel` |
| 4 | Tela "Avaliação" com o placar no frontend | `GET /evaluation/scoreboard` · `EvaluationScoreboard` |

O contrato OpenAPI passou de 1.1.0 para **1.2.0**. A mudança é só aditiva: um frontend 1.1.0 continua funcionando, e o frontend novo esconde os painéis se o backend for antigo.

## Números (corpus sintético, 12 cenários, 2 deles propositalmente vagos)

| Configuração | Aprovados | Válidos | Cobertura | Invenções | Latência média | Custo por processo |
|---|---|---|---|---|---|---|
| Sonnet · antes (sem gate/reparo) | 10/12 | 100% | 92% | 0 | 7,7 s | US$ 0,015 |
| **Sonnet · depois** | **12/12** | 100% | 100% | 0 | 8,6 s | US$ 0,019 |
| Haiku 5.5 · depois | 9/12 | 83% | 83% | 0 | 22,2 s | US$ 0,175 |

- As duas falhas do "antes" eram pedidos vagos que viravam processo sem nenhuma pergunta. No "depois", o sistema pergunta primeiro e gera depois.
- **O modelo "barato" saiu 9 vezes mais caro por processo válido.** O Haiku 5.5 usou 22 mil tokens por cenário (contra 9,4 mil do Sonnet), repetiu perguntas e precisou de mais rodadas. Custo por token não é custo por resultado, e só o placar revela isso. Os custos são os informados pelo CLI (preço de tabela) e devem ser conferidos na fatura antes de qualquer afirmação pública.
- No Claude Code CLI, o apelido `haiku` aponta para o Haiku 4.5. Para o modelo atual, use o ID completo `claude-haiku-5-5`. O Haiku também precisa de `AI_TIMEOUT_MS` maior (170 s), porque o padrão de 60 s estoura com o prompt completo.
- Na jornada da demo, o cache de prompt atendeu **77% dos tokens de entrada**. O conhecimento estável vai no início do prompt, por isso se repete entre chamadas e sai mais barato.
- Custo da sessão completa da demo (pergunta, proposta e refinamento): cerca de **US$ 0,03**.

Os números da última execução de cada configuração ficam em `reports/eval/SCOREBOARD.md`, que pode ser regenerado sem custo com `npm run eval:scoreboard`.

## Como subir a demo (Linux; portas dedicadas para não colidir com outros projetos)

```bash
# 1. PostgreSQL descartável (apenas local; escolha uma senha local qualquer)
export PG_LOCAL_PASSWORD=defina-uma-senha-local
docker run -d --name process-ai-pilot-pg -e POSTGRES_DB=process_ai -e POSTGRES_USER=process_ai \
  -e POSTGRES_PASSWORD=$PG_LOCAL_PASSWORD -p 127.0.0.1:55440:5432 postgres:17-alpine
U=postgresql://process_ai:$PG_LOCAL_PASSWORD@127.0.0.1:55440/process_ai
MIGRATION_DATABASE_URL=$U DATABASE_URL=$U npm run db:migrate

# 2. Backend com Claude (usa o login do `claude` instalado; somente texto sintético)
HOST=127.0.0.1 PORT=3346 CORS_ORIGIN=http://127.0.0.1:5185 DATABASE_URL=$U \
  AI_PROVIDER=claude-cli EXTERNAL_AI_APPROVED=true AI_MODEL=sonnet AI_TIMEOUT_MS=120000 \
  CLAUDE_CLI_MAX_BUDGET_USD=0.5 node --import tsx src/server.ts

# 3. Frontend (no repositório process-ai-frontend)
VITE_API_BASE_URL=http://127.0.0.1:3346 npx vite --host 127.0.0.1 --port 5185 --strictPort
```

Node 22.12 ou superior (testado com 24.19). Para trocar de modelo durante a demo, reinicie o backend com `AI_MODEL=haiku` (ou outro), sem nenhuma mudança de código.

## Roteiro sugerido (8 minutos)

1. **Problema (1 min).** Descrever processo em linguagem natural é fácil. Gerar BPMN confiável não é: a LLM inventa etapas e regras.
2. **Arquitetura (1 min).** "A LLM propõe, o backend decide." Mostre a cadeia: contrato tipado → evidência literal → compilador → validação → artefatos determinísticos.
3. **Demo ao vivo (3 min).**
   - Digite *"Quero criar uma solicitação de férias para aprovação do gestor."* O sistema resume o que entendeu e faz 3 perguntas, sem gerar nada ainda.
   - Responda às perguntas. Sai uma proposta válida em cerca de 5 s, com BPMN, formulários e o painel "O que entendi" mostrando a origem de cada item.
   - Mostre "O que falta": as atribuições de runtime pendentes mantêm a publicação bloqueada. Isso é intencional.
   - Mostre "Custo e desempenho": custo do turno, cache e etapas do pipeline.
   - Peça um refinamento: *"Depois que o RH registrar as férias, o servidor deve ser notificado da aprovação."*
4. **Placar (2 min).** Aba "Avaliação": antes × depois e Sonnet × Haiku. A melhora veio da casca (gate e reparo), não da troca de modelo.
5. **Próximos passos (1 min).** Ver abaixo.

Contingência: se a rede ou o provedor falhar, mostre o card de recuperação ("Tentar novamente", texto preservado) e as capturas em `piloto-20261022/`.

## Limites a declarar

- POC local, sem autenticação corporativa. Somente dados sintéticos. Publicação e execução continuam bloqueadas.
- A assinatura do Claude Code serve para a demo local. Para o **piloto com usuários**, use a API da Anthropic com chave corporativa (`CLAUDE_CLI_BARE=true` e `ANTHROPIC_API_KEY` por mecanismo aprovado) e a aprovação de dados exigida em `specs/active/04-seguranca-qualidade.md`.
- O gate de prontidão é heurístico (verbos e pistas no texto do solicitante). Ele pergunta no máximo uma rodada e nunca afrouxa validação.
- Pendência pré-existente: o teste `AI_GRAPH_IR_MODE controlled rejects … role assigned to the wrong evidence` falha na `main`. O modo GraphIR fica desligado por padrão e não é usado na demo.

## Próximos passos propostos

1. Ampliar o corpus para 30 ou mais cenários, incluindo exemplos negativos e refinamentos, e rodá-lo no CI a cada mudança de prompt ou modelo.
2. Refinamento por operações tipadas (`change_set`) com diff visual. Precisa de um ADR próprio.
3. Roteamento de modelos: Haiku para perguntar e classificar, Sonnet para compilar, guiado pelo placar.
4. Guardar pares "pedido → proposta aceita" como dataset para few-shot dinâmico e, no futuro, fine-tuning de modelo pequeno.
